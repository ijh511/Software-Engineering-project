# 소프트웨어공학 프로젝트 제안서

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 렌터카 예약 및 차량 관리 시스템 (Car Rental Management System) |
| 과목 | 소프트웨어공학 |
| 프로젝트 유형 | Frontend / Backend 분리형 웹 애플리케이션 |
| 개발 목표 | 사용자가 차량을 조회·선택·대여·반납·결제하고, 관리자가 차량과 대여 현황을 관리하는 시스템 구현 |

### 1.1 주제 선정 배경
렌터카 서비스를 이용할 때 차량 종류, 대여 가능 여부, 기간별 요금 등을 한눈에 확인하기 어려울 수 있다. 또한 차량의 수량과 대여 상태를 체계적으로 관리하지 않으면 이미 대여된 차량이 중복으로 예약되는 문제가 발생할 수 있다. 이러한 문제를 해결하기 위해 사용자에게는 간편한 렌터카 이용 기능을, 관리자에게는 차량 및 대여 현황 관리 기능을 제공하는 웹 기반 시스템을 개발하고자 한다.

### 1.2 프로젝트 목표
- 사용자가 차종별 차량 정보와 대여 가능 수량을 확인하고 차량을 선택할 수 있도록 한다.
- 사용자가 대여 시작일과 반납 예정일을 선택하면 예상 요금을 계산한다.
- 대여 가능한 차량이 없으면 대여를 제한하여 중복 대여를 방지한다.
- 차량 반납 시 실제 이용 기간에 따른 최종 요금을 계산하고 결제 상태를 기록한다.
- 관리자가 차종별 가격, 전체 차량 수량, 차량 상태 및 대여 내역을 관리할 수 있도록 한다.

## 3. 주요 구현 기능

### 3.1 사용자 기능 (Frontend 중심)

| 기능 | 상세 설명 |
|---|---|
| 차량 목록 조회 | 보유 중인 차량의 이름, 차종, 기본 요금, 대여 가능 여부 표시 |
| 차량 검색 및 선택 | 차종이나 가격 범위 등을 기준으로 차량을 검색하고 선택 |
| 차량 상세 정보 | 차량 이미지(선택), 차종, 일일 요금, 현재 대여 가능 수량 확인 |
| 차량 대여 신청 | 대여 시작일과 반납 예정일을 입력하여 예약 또는 대여 요청 |
| 예상 요금 확인 | 선택한 차종의 일일 요금과 대여 일수를 바탕으로 예상 금액 표시 |
| 대여 내역 조회 | 사용자의 예약 및 대여 내역, 진행 상태 확인 |
| 차량 반납 요청 | 대여한 차량의 반납 처리 요청 및 최종 금액 확인 |
| 결제 상태 확인 | 결제 예정·완료 등의 상태와 금액 확인 |

### 3.2 서버 기능 (Backend 중심)

| 기능 | 상세 설명 |
|---|---|
| 차량 정보 관리 | 차량별 고유 ID, 차종, 가격, 상태 등의 데이터 저장 및 조회 |
| 차종별 가격 설정 | 관리자가 차종별 일일 대여 요금을 설정·수정 |
| 차량 수량 관리 | 전체 차량 수, 대여 중 차량 수, 대여 가능 차량 수 관리 |
| 대여 가능 여부 검증 | 요청 기간에 이용 가능한 차량이 있는지 서버에서 확인하고, 없으면 대여 거절 |
| 예약 및 대여 처리 | 대여 기록 생성, 대여 상태 변경, 동일 차량 중복 배정 방지 |
| 반납 처리 | 차량 반납 시 상태를 변경하고 이용 가능한 차량 수에 반영 |
| 최종 요금 계산 | 대여 기간과 실제 반납 시점을 반영하여 최종 결제 금액 계산 |
| 결제 기록 관리 | 모의 결제 처리 및 결제 내역·상태 저장 (실제 카드 결제 연동은 기본 범위에서 제외) |
| 관리자 기능 | 차량 추가·수정·삭제, 차량 상태 변경, 전체 대여 내역 조회 |

### 3.3 추가 구현 기능 (기본 수업·과제 기능과 차별화)
- **기간별 재고 확인:** 전체 차량 수량만 확인하는 것이 아니라 선택한 대여 기간에 실제로 이용 가능한 차량을 계산한다.
- **중복 예약 방지:** 두 사용자가 동시에 마지막 남은 차량을 신청하더라도 서버에서 재고를 검증해 초과 예약을 막는다.
- **상태 기반 관리:** 차량 상태(대여 가능·대여 중·정비 중)와 대여 상태(예약·대여 중·반납 완료)를 구분한다.
- **자동 요금 계산:** 대여 일수에 따른 예상 요금과 반납 시 최종 요금을 자동으로 계산한다.
- **관리자 대시보드:** 전체 차량 수, 대여 중인 차량 수, 대여 가능 차량 수와 대여 내역을 한 화면에서 조회한다.

## 4. 시스템 설계

### 4.1 전체 구조

```text
[사용자 / 관리자]
        |
        v
[Frontend: 웹 화면]
  - 차량 조회 및 선택
  - 예약 / 반납 / 결제 화면
  - 관리자 대시보드
        |
        | HTTP 요청 / JSON 응답 (REST API)
        v
[Backend: 서버]
  - 차량 및 차종 관리
  - 예약·대여·반납 처리
  - 재고 검증 및 요금 계산
  - 모의 결제 상태 관리
        |
        v
[Database]
  - 차량 / 차종
  - 사용자
  - 대여 기록
  - 결제 기록
```

### 4.2 주요 데이터 설계(안)

| 데이터 | 주요 속성 |
|---|---|
| User | 사용자 ID, 이름, 연락처, 권한 |
| CarType | 차종 ID, 차종명, 일일 대여 요금 |
| Car | 차량 ID, 차종 ID, 차량 번호, 상태 |
| Rental | 대여 ID, 사용자 ID, 차량 ID, 시작일, 반납 예정일, 실제 반납일, 대여 상태 |
| Payment | 결제 ID, 대여 ID, 최종 금액, 결제 상태, 결제 일시 |


### 4.3 기본 이용 흐름
1. 사용자가 차량 목록과 차종별 가격을 확인한다.
2. 원하는 차량과 대여 기간을 선택한다.
3. 서버가 해당 기간의 차량 재고를 확인한다.
4. 차량이 있으면 예상 요금을 보여주고 대여를 확정한다. 없으면 대여 불가 메시지를 표시한다.
5. 사용자가 대여 내역을 조회하고 이용을 마친 뒤 반납한다.
6. 서버가 최종 요금을 계산하고 모의 결제를 처리한다.
7. 반납 완료 차량을 다시 대여 가능 상태로 변경한다. 단, 정비가 필요한 차량은 제외한다.

## 6. 테스트 계획 및 완료 기준

| 테스트 상황 | 기대 결과 |
|---|---|
| 차량 재고가 있는 경우 대여 요청 | 대여 성공 및 해당 기간의 가용 수량 감소 |
| 선택 기간에 차량 재고가 0대인 경우 | 대여 불가 안내 및 대여 기록 미생성 |
| 마지막 남은 차량에 동시 대여 요청 | 하나만 성공하고 초과 예약은 차단 |
| 차종별 일일 요금이 다른 경우 | 선택한 차종과 대여 일수에 맞는 금액 계산 |
| 차량 반납 및 결제 처리 | 최종 금액·결제 상태 기록, 차량 상태 갱신 |
| 정비 중인 차량 선택 | 대여 가능 목록에서 제외 또는 대여 불가 표시 |
| 관리자 가격 변경 | 이후 새로 신청하는 대여의 예상 요금에 변경된 가격 반영 |
